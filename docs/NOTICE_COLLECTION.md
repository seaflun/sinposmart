# 通報自動收取

## 使用方式

在帳號選擇視窗開啟「通報帳號設定」，為固定帳號 tyfd01214 儲存密碼並驗證登入。通報帳密獨立以 Windows DPAPI 保存，不跟隨當班人員切換、不讀取 Chrome 密碼庫，也不隨更新包或 NAS 帳密同步傳送；公務電腦需在當地設定一次。

GUI 開啟或縮到系統匣時持續檢查，勤務登出後仍保留排程；真正退出 GUI 時停止。臺灣時間 08:00 至 22:00 每 3 分鐘檢查，其餘每 30 分鐘。正式勤務、交接及工具優先，忙碌時合併成一次待執行。

通報卡片以標題右上角單一圓點顯示提醒與作業狀態：本班已有通報時持續紅色；本班尚無通報時，實際收取或登入驗證執行中為綠色，其餘為藍色。滑鼠移到標題可查看等待排程、執行中、等待作業、登入驗證中、失敗、待確認、停止中或已停止等完整狀態。今日累積合計當日自動收取及依公布日歸屬的手動收取，同一識別碼只計一次；當班自動收取及新增入表收據不混入人工數。

## 簽收責任

簽收只採用正式應有值退及值班紀錄都已確認的交班組，不按排班鐘點或最後登入者切換。未返隊暫停時維持前一位已確認值班者；部分登打、近似比對、取消、多人或即時證據不足時留白待人工確認。已確認人員可跨登出與班表換日保留；重啟後無足夠正式證據時不猜人。

每則通報的責任人、職稱、收取時點及交班證明雜湊固定保存於原寫入意圖，跨時段及重啟重試不換人。handoffSlotAt 是交班組的排程錨點，capturedAt 才是責任人確認所對應的收取時點。雲端逐筆核對下拉選項並回報實際簽收；不同人回報不得以內容去重掩蓋。新列備註精簡為通報編號、收取時間、番號及姓名，SinpoSmart signing: 與番號姓名分成兩行，簽收選項顯示於 F 欄，不重複顯示姓名別名、責任時點或完整證明雜湊；詳細責任證明仍保留於 GUI 查核資料，既有簽收與人工備註不回填、不覆寫。

通報收取標題右上角紅點表示本班已有通報；以正式交班證明辨識同一班次，保留到下一次確認交班，排班時間到點、暫停交班、檢查失敗或暫時無法比對都不提前清除。自動收取從既有寫入收據復原提醒；首次補查到的手動收取通報，只有公布時間位於目前確認班次內才保留該班的顯示識別，重查不轉移到下一班，也不補寫正式簽收責任。舊公布日期的補查不點亮本班紅點。提醒識別只保存在本機，不送往後台。

本班紅色提醒優先於執行狀態，後續執行不改成綠色。藍色表示本班尚無通報提醒；登入、讀取或入表錯誤仍以原有警告／錯誤文字明確顯示，圓點不作為網站成功或健康證明。

提示卡片只在登入後的值班畫面顯示，位於每日／每月作業下方、勤務任務上方。正常文字為「當班時段已自動收取 X 則通報，今日累積 Y 則。」；當班計數依班表時段，今日以臺灣時間 00:00 分界。正常單行卡片保持 44px，異常或換行時才擴高。

## 交班前通報提醒

登入值班模式且番號屬於當班時，依班表交班時間提前兩分鐘顯示獨立置頂視窗。連續由同人值班的時段會合併，只在真正交班前提醒。只列原收取時間位於當班、已確認入表的自動收取紀錄；0 則不彈出。每班提醒一次，本機保存提醒識別，程式重開不重複；登出、審核模式或班界過後隱藏。

視窗使用正式 GUI 的字型、配色與按鈕，非模態，不阻擋勤務登打與交接。最後檢查顯示在值班時段後；清單依收取時間排序，發布人上列單位、下列姓名，長主旨換行，資料過多時捲動。視窗開啟期間更新已確認的資料；暫時讀取失敗保留同班上次確認清單並提示。按「我知道了」僅關閉提醒，不修改已讀或簽收。

本機另保存原始發布人供顯示，保留斜線前的單位；既有雲端 sender 格式與待確認寫入意圖保持相容。舊紀錄利用既有已讀補查，按相同通報識別補齊發布人，不更動原收取時間、計數或簽收。來源缺漏時顯示未提供，不推測人員。

「開啟通報試算表」在背景呼叫既有 `getMonthlySpreadsheetLink` 唯讀介面，核對年月、文件識別及官方 Google Sheets URL 後開啟；不建立月檔、不寫入試算表，無法確認則提示重試。

## 收取流程

專用背景 Chrome 在目前工作階段存活期間沿用入口網登入狀態。首次或 session 過期時使用共用 OCR 登入流程，失敗保留明確異常；不能把登入頁當作沒有通報。設定新密碼後以全新工作階段驗證，不借舊 session 宣告成功。

通報使用既有 `build_driver` 的 Chrome 啟動復原包裝，依原有次數上限重試（預設 2 次），每次建立獨立且有所有權標記的專用 profile。通報快取與其他工具隔離，停用舊 profile 掃除；原先的固定 profile 保留。正常關閉只清理本次建立的專用 profile。此重試只涵蓋 Chrome 建立，登入、讀取、寫入與已讀仍維持原有確認流程。

先確認未讀篩選與分頁完整性。沒有未讀時不擷取內文、不寫試算表；有未讀時先比對已存在與內文完整性，必要時才讀取內容。沿用 Apps Script 的 requestId、寫入收據與去重規則，確認成功入表後才標已讀，再重載未讀清單核對。結果不確定時保留待確認狀態，避免盲目重送或先標已讀。

每輪查詢與標記已讀後的回查均明確重新載入通報頁，避免相同含 `#` 的網址只在原文件內導覽，沿用先前的空列表或已讀前資料。

本機僅保存去重識別與必要確認 metadata，不保存完整通報內文、密碼、token 或 cookie。

## 月檔與跨年

Apps Script 來源及 19 項測試位於 `google_notice_collection/`。真正寫入時，缺少月份檔便整份複製母檔並放入正確民國年度；年度不存在時自動建立。查詢未讀及 `checkExisting` 不會預先建檔。刪除空白測試月檔後，未來該月份第一次實際寫入仍可重建。

2026-10-22 已以正式第 9 版的建立函式實測 115 年 11 月與 116 年 1 月，確認年度父資料夾、唯一月檔、33 分頁、3,416 條公式、主要格式及人員下拉；檔名／日期自訂函式分別算出 2026-11-01、2027-01-01，測試格已清空，母檔未修改。

## 值班後台「已收通報」

公務 GUI 透過既有後台事件佇列回報通報檢查結果。零未讀仍更新最後檢查時間，背景忙碌與缺少設定也會明確回報；登入驗證不當作收取成功。回報只含來源電腦、時間、確認入表的識別雜湊與主旨、已讀確認及安全錯誤分類，不傳送內文或憑證。

後台在每日彙總下方顯示當班／臺灣曆日累計、最後檢查、最近新增、下次檢查及來源電腦。曆日查詢與原有消防日獨立；沒有回報或明細分片不完整時顯示待確認，不將未知計數當作零筆。只有新增或異常保留輪次明細，零筆檢查不洗版。已入表但未完成已讀確認會保留已成功筆數並標示待完成。

升級後沿用本機已確認收取的 ledger，按原收取時間計數與去重；舊 ledger 未保存的主旨或已讀狀態不回推補造。試算表按所選曆日年月開啟雲端檔名搜尋，跨月份不寫死檔案 ID。詳細回報分片沿用原事件 ID 重試，避免因延後確認、斷線或重啟重複計數。

## 驗證界線

模擬測試涵蓋未讀比對、寫入／收據回查、去重、已讀確認、跨日計數、排程與安全結束，並包含首次空列表後新增通報，以及標記已讀後取得最新列表的回歸。真實背景登入及雲端月份建立已完成驗收。

2026-10-22 本機 GUI 實際收取 5 則正式未讀通報，5 則寫入收據與試算表回查一致；重新載入公務網站後確認未讀為 0。此次找出並修正相同 fragment 導覽沿用舊文件的問題，修正後以連續兩輪實站查詢確認每輪均取得新文件。公務電腦套用修正版後的自動排程驗收仍須另行確認。
