# 通報自動收取

## 使用方式

在帳號選擇視窗開啟「通報帳號設定」，為固定帳號 tyfd01214 儲存密碼並驗證登入。通報帳密獨立以 Windows DPAPI 保存，不跟隨當班人員切換、不讀取 Chrome 密碼庫，也不隨更新包或 NAS 帳密同步傳送；公務電腦需在當地設定一次。

GUI 開啟或縮到系統匣時持續檢查，勤務登出後仍保留排程；真正退出 GUI 時停止。臺灣時間 08:00 至 22:00 每 3 分鐘檢查，其餘每 30 分鐘。正式勤務、交接及工具優先，忙碌時合併成一次待執行。

提示卡片只在登入後的值班畫面顯示，位於每日／每月作業下方、勤務任務上方。正常文字為「當班時段已自動收取 X 則通報，今日累積 Y 則。」；當班計數依班表時段，今日以臺灣時間 00:00 分界。正常單行卡片保持 44px，異常或換行時才擴高。

## 收取流程

專用背景 Chrome 沿用入口網登入狀態。首次或 session 過期時使用共用 OCR 登入流程，失敗保留明確異常；不能把登入頁當作沒有通報。設定新密碼後以全新工作階段驗證，不借舊 session 宣告成功。

先確認未讀篩選與分頁完整性。沒有未讀時不擷取內文、不寫試算表；有未讀時先比對已存在與內文完整性，必要時才讀取內容。沿用 Apps Script 的 requestId、寫入收據與去重規則，確認成功入表後才標已讀，再重載未讀清單核對。結果不確定時保留待確認狀態，避免盲目重送或先標已讀。

每輪查詢與標記已讀後的回查均明確重新載入通報頁，避免相同含 `#` 的網址只在原文件內導覽，沿用先前的空列表或已讀前資料。

本機僅保存去重識別與必要確認 metadata，不保存完整通報內文、密碼、token 或 cookie。

## 月檔與跨年

Apps Script 來源及 19 項測試位於 `google_notice_collection/`。真正寫入時，缺少月份檔便整份複製母檔並放入正確民國年度；年度不存在時自動建立。查詢未讀及 `checkExisting` 不會預先建檔。刪除空白測試月檔後，未來該月份第一次實際寫入仍可重建。

2026-10-22 已以正式第 9 版的建立函式實測 115 年 11 月與 116 年 1 月，確認年度父資料夾、唯一月檔、33 分頁、3,416 條公式、主要格式及人員下拉；檔名／日期自訂函式分別算出 2026-11-01、2027-01-01，測試格已清空，母檔未修改。

## 值班後台「已收通報」

公務 GUI 透過既有後台事件佇列回報通報檢查結果。零未讀仍更新最後檢查時間，背景忙碌與缺少設定也會明確回報；登入驗證不當作收取成功。回報只含來源電腦、時間、確認入表的識別雜湊與主旨、已讀確認及安全錯誤分類，不傳送內文或憑證。

後台在每日彙總下方顯示當班／臺灣曆日累計、最後檢查、最近新增、下次檢查及來源電腦。曆日查詢與原有消防日獨立；沒有回報或明細分片不完整時顯示待確認，不將未知計數當作零筆。只有新增或異常保留輪次明細，零筆檢查不洗版。已入表但未完成已讀確認會保留已成功筆數並標示待完成。

升級後沿用本機已確認收取的 ledger，按原收取時間計數與去重；舊 ledger 未保存的主旨或已讀狀態不回推補造。試算表按所選曆日年月開啟雲端檔名搜尋，跨月份不寫死檔案 ID。詳細回報分片沿用原事件 ID 重試，避免因延後確認、斷線或重啟重複計數。

## 驗證界線

模擬測試涵蓋未讀比對、寫入／收據回查、去重、已讀確認、跨日計數、排程與安全結束，並包含首次空列表後新增通報，以及標記已讀後取得最新列表的回歸。真實背景登入及雲端月份建立已完成驗收。
